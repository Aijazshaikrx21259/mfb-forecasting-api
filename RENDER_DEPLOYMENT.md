# Render Deployment Guide

This guide explains how to deploy the MFB Forecasting API to Render's free tier.

## Why Render Instead of Vercel?

Vercel has a 250 MB limit for serverless functions, which is insufficient for data science libraries like:
- `pandas` (~100 MB)
- `numpy` (~50 MB)
- `scipy` (~90 MB)
- `statsforecast` (~40 MB)

Render supports full Docker deployments with no size restrictions, making it perfect for ML/data science APIs.

## Deployment Steps

### Option 1: Automatic Deployment (Blueprint - Recommended)

1. **Push your code to GitHub** (if not already done)
   ```bash
   git add .
   git commit -m "Chore(deploy): migrate from Vercel to Render"
   git push origin main
   ```

2. **Go to [Render Dashboard](https://dashboard.render.com/)**
   - Sign up or log in with your GitHub account

3. **Create New → Blueprint**
   - Connect your GitHub repository
   - Render will automatically detect `render.yaml`
   - Click "Apply" to create the service

4. **Configure Environment Variables**
   - `DATABASE_URL`: Your PostgreSQL connection string (if applicable)
   - `API_KEY`: Will be auto-generated (or set your own)
   - `ALLOWED_ORIGINS`: Set to your frontend domain or keep `*` for development

### Option 2: Manual Web Service Creation

1. **Go to [Render Dashboard](https://dashboard.render.com/)**

2. **Create New → Web Service**

3. **Connect Repository**
   - Select your GitHub repository
   - Branch: `main`

4. **Configure Service**
   - **Name**: `mfb-forecasting-api`
   - **Region**: Oregon (US West) - Free tier available
   - **Branch**: `main`
   - **Runtime**: Python 3
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
   - **Plan**: Free

5. **Add Environment Variables**
   ```
   ENVIRONMENT=production
   PIPELINE_AUTO_RUN=false
   DATABASE_URL=<your-database-url>
   API_KEY=<generate-a-secure-key>
   ALLOWED_ORIGINS=*
   ```

6. **Deploy**
   - Click "Create Web Service"
   - Wait for the build to complete (~5-10 minutes)

## Environment Variables Explained

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `DATABASE_URL` | No | None | PostgreSQL connection string for Neon DB |
| `API_KEY` | Yes | - | API key for authentication (auto-generated by Render) |
| `ENVIRONMENT` | No | `development` | Environment name (production/development) |
| `PIPELINE_AUTO_RUN` | No | `false` | Enable automatic forecast pipeline runs |
| `PIPELINE_RUN_ON_DEMAND` | No | `false` | Allow on-demand pipeline triggers |
| `ALLOWED_ORIGINS` | No | `*` | CORS allowed origins (comma-separated) |

## After Deployment

1. **Check Service Health**
   - Visit: `https://your-service-name.onrender.com/health`
   - Should return: `{"status": "ok"}`

2. **View API Documentation**
   - Visit: `https://your-service-name.onrender.com/docs`
   - Interactive Swagger UI

3. **Test an Endpoint**
   ```bash
   curl -H "X-API-Key: YOUR_API_KEY" \
        https://your-service-name.onrender.com/health
   ```

## Free Tier Limitations

- **Sleep after 15 minutes of inactivity** - First request after sleep takes ~30 seconds
- **750 hours/month** - Enough for continuous running if it's your only service
- **No custom domains** on free tier
- **Shared CPU/RAM** - Performance may vary

## Keeping Service Awake (Optional)

To prevent sleeping, you can use a free uptime monitor:

1. **UptimeRobot** (https://uptimerobot.com)
   - Create a new monitor
   - Type: HTTP(s)
   - URL: `https://your-service-name.onrender.com/health`
   - Interval: Every 5 minutes

2. **Cron-job.org** (https://cron-job.org)
   - Create a new cron job
   - URL: Your health endpoint
   - Interval: Every 10 minutes

## Troubleshooting

### Build Fails

**Issue**: Dependencies installation timeout
```
Solution: Render free tier has limited resources. Dependencies should install fine,
but if it times out, try again. The build cache helps subsequent builds.
```

### Service Won't Start

**Issue**: Port binding error
```
Solution: Ensure your start command uses $PORT environment variable.
Render injects this automatically.
```

### 503 Service Unavailable

**Issue**: Service is sleeping (free tier)
```
Solution: Wait 30-60 seconds for cold start, or set up uptime monitoring.
```

### Database Connection Issues

**Issue**: Cannot connect to Neon DB
```
Solution: 
1. Verify DATABASE_URL is set correctly
2. Check Neon DB allows connections from Render IPs
3. Neon free tier requires periodic wake-up similar to Render
```

## Upgrading from Free Tier

If you need:
- **No sleep** - Upgrade to Starter ($7/month)
- **More resources** - Starter gets 0.5 GB RAM, 0.5 CPU
- **Custom domains** - Available on paid plans

## Alternative Free Platforms

If Render doesn't work out:

1. **Railway** (https://railway.app)
   - $5 free credit/month
   - No sleep
   - Better for databases

2. **Fly.io** (https://fly.io)
   - Free allowances
   - Edge deployment
   - More complex setup

3. **Cyclic** (https://cyclic.sh)
   - Unlimited free tier
   - Good for Node.js primarily
